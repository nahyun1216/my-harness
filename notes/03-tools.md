# 3회차 — 3장 Tools: JSON을 함수에 연결하기 (2026-10-29 ~ 2026-10-30)

## 3줄 요약
- **고장**: 모델은 글자만 쓸 수 있다. "테스트 통과했는지 봐줘"라고 해도 추측만 한다.
- **패치**: 모델이 "이 함수를 이 값으로 실행해줘"라는 **JSON 요청서(tool_use)**를 쓰면, **하네스가 대신 실행**하고 결과(tool_result)를 배열에 넣어준다.
- **핵심**: 모델은 **요청만**, 실행하는 손은 **하네스**. 그래서 능력도 안전도 하네스 책임.

## 비유: 식당 🍽️
모델 = 주방에 못 들어가는 손님. 주문만 할 수 있다.

| 식당 | 하네스 세계 | JSON |
|---|---|---|
| 메뉴판 | 쓸 수 있는 함수 목록 | `tools` (요청에 같이 보냄) |
| 주문서 | "read_file 을 main.py 로" | `tool_use` 블록 (모델 답) |
| 주방 | 하네스가 진짜 함수 실행 | `execute_tool()` |
| 서빙 | 결과를 배열에 넣어줌 | `tool_result` 블록 (다음 메시지) |

## 흐름
```
 [하네스 (내 노트북)]                        [모델 (Anthropic)]
        │                                          │
   ①   │── messages + tools(메뉴판) ─────────────▶│
        │                                          │  "파일을 봐야겠다"
   ②   │◀── tool_use: read_file {"path":"a.py"} ──│  (주문서만 씀)
        │                                          │
   ③   │  open("a.py").read()  ← 진짜 실행은 여기!
        │                                          │
   ④   │── messages + tool_result:"import sys..." ▶│
        │                                          │
   ⑤   │◀── "12번째 줄에 버그가 있어요" ──────────│
```
API 호출 2번. ④에서 배열 전체를 다시 보냄 (1장과 같은 원리).

## 꼭 기억할 것
- `description` = 모델이 보는 **유일한 설명서**. 대충 쓰면 엉뚱하게 씀.
- `tool_result` 는 **`role: user`** 로 들어간다. 세상의 대답은 사용자 자리로.
- `tool_use_id` 로 주문서–요리 짝을 맞춘다. 짝이 안 맞으면 API 에러.
- 모델이 JSON을 잘 쓰는 건 **RL 훈련** 덕분 (2장). 도구 = 메뉴판 + dict 찾기.
- 에러는 `raise` 말고 **문자열로 돌려준다** → 모델이 스스로 고칠 기회.
- v2 한계: 도구를 **딱 한 번**만 실행 → 4장 Agent Loop 가 해결.

## 덤 개념
- **사용자도 도구** (`ask_user_question`): 질문을 띄우고 사람 답을 tool_result 로. Claude Code 객관식 창이 이것.
- **구조화된 출력**: 실행 안 하는 가짜 도구(`report_answer`)를 강제 호출 → 인자가 곧 원하는 JSON 답.
- **서버 측 도구** (`web_search` 등): 제공사가 실행. 내 하네스를 안 거쳐서 기록·차단·수정 불가.

## 개념 퀴즈 (내 답 → 보충)
1. tool_use 의 함수는 누가, 어디서 실행?
   - 내 답: 하네스가, 로컬(Edge)에서.
   - 보충: 정답. 더 정확히는 "**하네스가 돌고 있는 곳**". 보통 내 노트북이지만, 하네스가 클라우드 서버에서 돌면(예: 웹 버전 Claude Code) 거기서 실행됨. 핵심은 **모델 쪽이 아니라 하네스 쪽**이라는 것.
2. tool_result 의 role?
   - 내 답: user.
   - 보충: 정답.
3. 모델의 유일한 설명서?
   - 내 답: tool 의 description.
   - 보충: 정답. (+ `input_schema` 의 각 인자 설명도 같이 읽음)
4. 에러를 왜 문자열로 돌려주나?
   - 내 답: 프로그램이 중단되면 루프가 끊길 수 있으니까.
   - 보충: 반은 맞음. 두 가지 이유:
     - **배열이 날아간다**: 프로그램이 죽으면 하네스 메모리에 있던 배열(= 대화 기억 전부)이 사라짐 (1장).
     - **에러는 모델의 힌트**다: "파일 없음"을 받으면 모델은 경로를 바꿔 재시도함 (2장 규칙 6, RL로 배운 습관). 에러를 숨기거나 죽으면 **스스로 고칠 기회**를 빼앗음.
5. 서버 측 도구를 쓰면 안 되는 경우?
   - 내 답: (b) 회사 DB 삭제. 이유는 모름.
   - 보충: 정답. 서버 측 도구는 **제공사 서버에서 실행**되어 내 하네스를 **거치지 않는다** →
     - 실행 전 "정말 삭제할까요?" 확인(승인)을 **끼워넣을 수 없음** (13장)
     - 무슨 일이 있었는지 **로그를 남길 수 없음**
     - 제공사가 내 DB에 접근하려면 **회사 DB 접속 정보를 외부에 넘겨야** 함
     - 웹 검색은 틀려도 피해가 작지만, DB 삭제는 **되돌릴 수 없음**.
6. Claude Code 객관식 질문의 원리?
   - 내 답: 사용자를 도구로 쓰는 것. 사용자가 줘야 할 답이 있을 때 호출.
   - 보충: 정답. 사람 답도 **tool_result 로 똑같이** 돌아감 — 파일 읽기와 같은 형식. 언제 물어볼지는 모델이 description("결정이 막혔을 때")과 훈련으로 판단.

## my_v2.py 코드 읽기
```
my_v2.py
├─ 17~19  설정값        API 키, 모델, system 프롬프트       → 식당 간판
├─ 21~32  TOOLS         도구 목록                          → 🍽️ 메뉴판
├─ 35~45  call_llm()    모델에게 배열 보내기 (API 호출)      → 📞 손님에게 주문 받기
├─ 48~58  execute_tool() 도구 이름 → 진짜 함수 실행          → 👨‍🍳 주방
└─ 72~    main()        전체 흐름: 입력→호출→실행→재호출      → 🧑‍💼 매니저
```
- **TOOLS** 는 코드가 아니라 데이터(안내문). 진짜 기능은 주방(`execute_tool`)에 있음.
- **call_llm** 은 my_v1 과 거의 같고 `"tools": TOOLS` 한 줄만 추가.
- **execute_tool** = if 문으로 이름 보고 함수 실행 (dispatch). `except` 에서 에러를 글자로 돌려줌.
- **main** 한 턴: 질문 추가 → 호출① → 주문서 1개만 실행 → tool_result(user) 추가 → 호출② → 또 주문하면 `[버려짐]`.

"이 폴더에 뭐가 있어?" 한 번에 배열이 **4칸** 늘고 API는 **2번** 호출:

| 단계 | 배열 변화 | 화면 |
|---|---|---|
| 82줄 | `[user: "이 폴더에 뭐가 있어?"]` | |
| 84→89줄 | `+ [assistant: tool_use list_dir {"path":"."}]` | `[tool_use] {...}` |
| 92줄 | (주방에서 `os.listdir(".")` 실행) | `[tool_result] '...'` |
| 95줄 | `+ [user: tool_result "..."]` | |
| 98줄 | `+ [assistant: "이 폴더에는 ..."]` | `assistant> ...` |

원본 대비: `run_command` → `list_dir`(안전), `[tool_use]`/`[tool_result]` 출력, `[버려짐]` 표시, API 에러 출력.

## 내 질문 & 답

### Q1. user = 나, assistant = 하네스 아닌가? 왜 user 가 도구를 실행한 것처럼 나와?
아니다. **role 은 "모델 입장에서" 나눈 것.**
- `assistant` = **모델 자신이 생성한 출력** (텍스트, tool_use). 하네스가 아님.
- `user` = **모델 바깥에서 들어온 입력 전부**. 사람이 친 글 + 하네스가 넣은 tool_result.
- **하네스는 role 이 아니다.** 배열을 관리하는 프로그램이라 배열에 등장하지 않음. 모든 메시지를 배열에 append 하는 건 하네스.

| 배열의 메시지 | role | 내용을 만든 것 | 배열에 넣은 것 |
|---|---|---|---|
| "제일 큰 파일 읽어줘" | user | 나 | 하네스 |
| tool_use list_dir | assistant | 모델 | 하네스 |
| tool_result (목록) | user | 하네스 (`execute_tool` 실행 결과) | 하네스 |
| "가장 큰 파일은 ..." | assistant | 모델 | 하네스 |

```
            ┌─────────── 하네스 (배열 관리, 도구 실행) ───────────┐
  나 ──입력──▶│  user: 질문                                        │
             │  assistant: tool_use   ◀── 모델 출력               │──▶ API (모델)
             │  user: tool_result     ◀── execute_tool() 결과     │
             │  assistant: 답변       ◀── 모델 출력               │
  나 ◀─출력──│                                                     │
             └─────────────────────────────────────────────────────┘
```
- `role: user` 는 "사람이 실행했다"가 아니라 **"모델이 만든 게 아니다(외부 입력이다)"** 라는 뜻.
- Anthropic API 는 user ↔ assistant 두 역할만 번갈아 쓰는 형식이라 도구 결과도 user 쪽에 들어감. (OpenAI API 는 `role: "tool"` 을 따로 둠 → 형식상 약속일 뿐)
- 그래서 3장 책에서 "the world answers on the user's channel" 이라고 표현함.

## 실습 관찰 (my_v2.py, 2026-10-30)
7. A("이 폴더에 뭐가 있어?")에서 모델이 고른 도구·인자?
   - 내 답: `list_dir`, `path` 로 `.` 을 넘김.
   - 보충: 정답. "이 폴더"를 모델이 스스로 `.`(현재 폴더)로 번역함. 메뉴판 description("List entries in a directory")만 보고 맞는 도구를 고른 것.
8. C(없는 파일)에서 에러를 받은 모델의 반응?
   - 내 답: 에러를 받아서 사용자에게 "찾을 수 없다"고 답함. 강제종료되지 않음.
   - 보충: 정답. `execute_tool` 의 `except` 가 에러를 **글자**로 돌려줬기 때문에 프로그램도 배열도 살아있음. 루프가 있다면(4장) 모델이 `list_dir` 로 비슷한 이름을 찾아보는 식으로 **스스로 고치기**도 함.
9. tool_use 와 tool_result 를 잇는 값?
   - 내 답: `id` ↔ `tool_use_id`. 그래서 루핑도 가능.
   - 보충: 정답. id 덕분에 주문이 여러 개여도 "어느 주문의 요리인지" 짝을 맞출 수 있음 (한 번에 여러 도구를 주문하는 병렬 호출도 가능). 다만 **루프 자체는 id가 아니라 코드**가 만든다 — "모델이 또 주문하면 또 실행" 을 반복하는 while 문 (4장).
10. G 다음 질문(H)에서 무슨 일이?
   - 결과: `[API ERROR 400] messages.4: tool_use ids were found without tool_result blocks immediately after`
   - 보충: tool_use 에 대응하는 tool_result 가 없는 배열을 보내서 API 가 거절한 것.
     ```
     [0] user      : 제일 큰 파일 읽어줘
     [1] assistant : tool_use list_dir(".")                         id=A
     [2] user      : tool_result (폴더 목록)                          tool_use_id=A  ✅
     [3] assistant : "CURRICULUM.md 읽겠습니다" + tool_use read_file  id=B
     [4] user      : "ㅇㅇ??"                    ← tool_use_id=B 인 tool_result 가 없음 ❌
     ```
     API 규칙: **assistant 메시지에 tool_use 가 있으면, 바로 다음 user 메시지에 같은 id 의 tool_result 가 있어야 한다.** v2 는 [3]의 read_file 을 실행하지 않고 다음 입력으로 넘어갔으므로 규칙 위반 → 400.
     [3]이 배열에 그대로 남아 있어서 이후 모든 요청이 같은 에러. `/quit` 후 새로 시작해야 함.
     → 교훈: 배열 형식을 API 규칙에 맞게 유지하는 건 **하네스의 책임**. 4장 루프는 응답에 tool_use 가 있는 동안 계속 실행 → tool_result 추가 → 재호출을 반복하므로 이 상태가 생기지 않음.

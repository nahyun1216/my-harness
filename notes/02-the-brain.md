# 2회차 — 2장 The Brain (2026-10-29)

## 3줄 요약
- 모델은 **"다음 토큰 확률표"만 만드는 기계**다. 고르고·이어 붙이고·반복하는 건 모델 밖(serving layer)이 한다. 기억·목표·상태 없음.
- 모델의 행동은 **훈련 3단계**로 설명된다: 사전훈련(지식, 환각) → 사후훈련(비서, system 프롬프트 따르기) → 과제 RL(도구 호출, thinking, 에러 보고 재시도).
- 그래서 하네스는 새 능력을 심는 게 아니라 **훈련된 능력을 활용**한다: 사실은 도구로 넣어주고, 에러는 돌려주고, 안전은 하네스가 지킨다.

## 핵심 개념
| 단어 | 쉬운 뜻 |
|---|---|
| 토큰 | 텍스트 조각(레고 블록). 비용·속도·한도가 전부 토큰 단위 |
| temperature | 확률표에서 얼마나 모험적으로 고를지. 0=항상 1등, 1=다양하게 |
| 컨텍스트 윈도우 | 한 번에 넣을 수 있는 최대 토큰 수 = 배열 크기 상한 |

| 훈련 단계 | 비유 | 하네스 입장에서 의미 |
|---|---|---|
| 사전훈련 | 도서관 책 전부 읽기 | 지식 + **환각**(그럴듯한 문장을 배웠지 참인 문장을 배운 게 아님) + 지식 컷오프 → 도구로 사실을 넣어줘야 함 |
| 사후훈련 | 비서 업무 교육 | system 프롬프트가 먹히는 이유 = 훈련. 강하지만 자물쇠는 아님 |
| 과제 RL | 실전 업무 + 성과급 | 도구 호출 JSON, thinking, 에러 보고 재시도 |

이미지·PDF도 결국 토큰. "대단한 기능"은 두뇌(모델)보다 몸(하네스)이 한 일이 많다.

## 작업 규칙 6개
1. 모델은 순수 함수 — 기억은 내 배열에
2. 기억(recall)보다 검색(retrieval) — 도구로 사실 주입
3. 역할은 훈련이지 강제가 아님
4. 도구·thinking은 훈련된 기술 — 정해진 형식으로 요청
5. 전부 토큰 — 이미지·생각·도구 호출 다 비용
6. 에러도 정보 — 모델에게 돌려줘라

## 내 질문 & 답

### Q1. serving layer(서버 프로그램)는 어디서 돌아가? 스레드마다 생기나? 하네스가 서버 프로그램?
**Anthropic 데이터센터**에서 돈다. 하네스도 아니고 내 PC도 아님.

```
[내 노트북]                                [Anthropic 데이터센터]
 Claude Code / my_brain.py  ──HTTP 요청──▶   serving layer (서버 프로그램)
   = 하네스                                    ├─ 모델: 확률표 계산 (GPU)
   - 배열 만들기                               └─ 확률표에서 토큰 고르기, 반복
   - 도구 실행
                            ◀──응답(JSON)──
```
- 하네스 = 내 쪽 (배열 만들고 보내고, 도구 실행). Claude Code도 `my_v1.py`도 하네스.
- Claude 창을 여러 개 띄우면 **하네스가 여러 개**. 모두 같은 API로 요청하고, 저쪽 서버들이 요청마다 처리.
- 내가 바꿀 수 있는 건 요청에 실어 보내는 **설정값**(temperature 등)뿐.
- 공개 모델(Llama 등)은 Ollama/vLLM으로 내 PC에서 serving layer를 직접 돌릴 수도 있음.

### Q2. 한국어보다 영어가 토큰 효율이 좋아?
대체로 그렇다. 토큰 사전이 영어 위주라 한국어가 더 잘게 쪼개짐.
다만 품질 차이는 작고, 영어 답을 읽는 내 시간도 비용.
**절충: 매번 반복되는 system 프롬프트·도구 설명은 영어, 대화는 편한 언어로.**

### Q3. temperature 내가 설정 가능? 기본값은?
- API 직접 호출 시 body에 `"temperature"` 로 설정 가능 (Anthropic: 0~1, **기본값 1.0**).
- claude.ai / Claude Code 같은 제품에서는 **하네스가 대신 정해서** 보내므로 사용자에겐 안 보임.
- 모델/기능 조합(예: thinking 켬)에 따라 변경이 막혀 있을 수 있음.
- temp=0 이어도 GPU 계산의 미세한 차이로 100% 동일하지 않을 수 있음.

### Q4. 배열을 효율화(요약 등)하는 과정도 있어?
있다 — 책 Part II 전체가 이 얘기.

| 방법 | 설명 | 회차 |
|---|---|---|
| 캐싱 | 앞부분이 같으면 할인 (줄이진 않음) | 5회 |
| truncate | 긴 도구 결과의 앞뒤만 남김 | 6회 |
| compaction | 오래된 대화를 요약으로 교체 | 7회 |
| 서브에이전트 | 새 배열에서 일하고 결과만 가져옴 | 8회 |

Claude Code의 auto-compact, `/compact` 도 하네스가 하는 일. 모델은 그런 일이 있었는지도 모른다.

## 실습 관찰 (my_brain.py)
같은 질문(배열)을 system / temperature 만 바꿔 5번 보냄.

1. A·B·C의 배열이 같은데 `in=`이 다른 이유?
   - 내 답: 메시지 토큰 수가 달라서.
   - 보충: messages는 5번 모두 **완전히 같다**. 다른 건 **system 프롬프트**. 모델에 들어가는 입력 = system + messages (+ tools) 전부이고, system도 토큰이라 `in=`에 포함된다. "배열 바깥 설정"처럼 보여도 결국 모델 입장에선 **한 줄로 이어진 토큰 시퀀스의 앞부분**.
2. C("No.만 답해")를 지켰나?
   - 내 답: 딱 지켰음.
   - 보충: 사후훈련으로 system에 권위를 주도록 배웠기 때문. 단, **강제가 아니라 훈련**이라 user가 집요하게 우기면 깨질 수도 있음 → 진짜 금지는 하네스가 막아야 함 (13장).
3. temperature 0 vs 1?
   - 결과: D(temp=0)는 `HTTP 400 "temperature is deprecated for this model."` / E(temp=1)는 정상 응답.
   - 보충: 이 모델은 **제공사가 temperature 조절 손잡이를 없앴다**. 고르는 방식은 serving layer(제공사)가 정하고, 우리는 받아들일 뿐. temp=1은 기본값과 같아서 통과한 것으로 보임.
     → "고르는 건 모델 밖"을 오히려 더 확실히 보여줌: 그 설정의 주인은 모델이 아니라 serving layer.
     → 하네스 교훈: **API 설정값은 모델/버전마다 바뀐다**. 에러를 죽이지 말고 출력하게 만든 덕분에 원인을 바로 봄 (규칙 6).
4. 한국어 vs 영어 토큰?
   - 내 답: 영어가 in/out 모두 적음.
   - 보충: Q2 확인 완료. 같은 내용이라도 한국어가 더 많은 토큰으로 쪼개짐.
5. 미래 질문(2030 월드컵)?
   - 내 답: 모른다고 했음.
   - 보충: 사후훈련·RL에서 "컷오프 이후는 모른다고 하기"를 배운 결과. 하지만 **애매한 사실(덜 유명한 API, 사내 정보 등)에선 여전히 그럴듯하게 지어낼 수 있음** → 규칙 2(기억 말고 검색)가 필요한 이유.

# 1회차 — 1장 It's Just a JSON Array (2026-10-27)

## 3줄 요약
- LLM API는 상태가 없다(stateless). 매 호출마다 대화 배열 **전체**를 보내고 답을 받는다.
- "기억"은 모델이 아니라 **하네스가 들고 있는 배열**에 있다. 배열에서 지우면 모델은 모른다.
- 하네스 = 그 배열을 만들고, 유지하고, 지키는 프로그램.

## 관찰 질문
1. 두 번째 질문에서 `in=`이 늘어난 이유?
   - 내 답: 대화가 길어져 토큰이 소모돼서.
   - 보충: 매 호출마다 이전 턴 전부 + 새 질문을 **다시 보내기** 때문. 그래서 `in=`은 "지금까지 쌓인 배열 크기".
2. `/forget` 후 이름을 모르는 이유? 기억은 어디에?
   - 내 답: 마지막 user+assistant 2개를 지워서. 기억은 배열 메시지로 존재.
   - 보충: 정답. 서버도 모델도 아무것도 저장하지 않음 → 기억의 주인은 하네스.
3. 100턴이 되면?
   - 내 답: 느려지거나 성능이 나빠질 듯.
   - 보충: 세 가지 문제.
     - 비용: 매 턴 전체를 재전송 → 누적 입력 토큰이 턴 수의 제곱에 비례해 증가 → **5장 캐싱**
     - 한도: 컨텍스트 윈도우를 넘으면 요청 자체가 에러 → **6장 truncate/compaction**
     - 품질: 길어질수록 앞쪽 내용을 놓치거나 흐려짐 → **6장, 7장 서브에이전트**
